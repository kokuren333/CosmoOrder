# 差分を読んでレビューする

差分（diff）は、二つのテキスト状態の違いを示します。Gitの一般的な表示では、`-` から始まる行が比較元で削除された行、`+` から始まる行が比較先に追加された行です。前後の文脈行は変更箇所の位置を読む助けになります。

```diff
diff --git a/settings.py b/settings.py
index 1111111..2222222 100644
--- a/settings.py
+++ b/settings.py
@@ -4,7 +4,7 @@
-timeout = 10
+timeout = 30
```

この差分から直接言えるのは、`timeout` の設定値が `10` から `30` に変わったことです。単位が秒か、待機処理にどう適用されるか、30が妥当か、設定が別環境で上書きされるかは、この数行だけでは判断できません。

## レビューの問い

- この変更が対応する要件や不具合は何か。説明と差分は一致しているか。
- 値の単位、許容範囲、既定値を定義や呼び出し元で確認したか。
- 境界値や待ち時間が異なるケースに影響しないか。関連するテストや利用箇所を見たか。
- 差分にない動作まで、見た目だけで「安全」「改善」と断定していないか。

レビューでは、観察（変更前後の行）と推論（利用者への影響）を分けて記録します。差分は提案されたテキスト変更を示すもので、それ自体がコードを適用・実行した証拠ではありません。

```diff
- timeout = 10
+ timeout = 30
```

Git公式の`git diff`マニュアルでは、差分表示が作業ツリーやcommit間など異なる状態を比較することが説明されています。どの二つの状態を比べているかも、レビュー時に確認します。
